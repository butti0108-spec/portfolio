# 見本30・文言厚化プラン（一括 → 個別 → 統合）

正本（Cursor Plan 承認版の控え）。実装・進捗は本ファイルと [STATUS.md](../_materials/STATUS.md) / [blocks.md](./blocks.md) を見る。

## 前提（固定）

- **1-A**: 全30の流れを設計する。着手は第1ブロックから。
- **2-C**: 前半の一括確認は **材料文言（`copy.json`）のみ**。見た目再判定は後半の個別。
- 品質: [quality-bar.md](./quality-bar.md) / [field-checklist.md](./field-checklist.md) / [30-plot.md](./30-plot.md)
- 調整は一万円サイト（編集ハブ）で再現できる手数だけ。見本専用ハック禁止。
- 文言の作業稿: `_materials/NN-…/copy.json` → 反映先: `NN-…/draft.json`
- 疑似文章エンジン: `sample-1man/easy-copy-dict.js`（刈り取りは統合フェーズ）

## 流れ

1. **前半（一括）**: P0 合格例＋ブロック表 → A1 `copy.json` 下書き → **A2 材料まとめて人確認で止める**
2. **後半（個別）**: B1 draft 反映 → B2 ダッシュ再判定 → B3 写真（別レーン可）
3. **最後（統合）**: C1 辞書刈り取り → C2 内部相性 → C3 5案実機確認

## 止め所

| ゲート | 内容 |
|--------|------|
| P0 | 合格例01＋ブロック表 |
| A2 | ブロックの `copy.json` 材料OK（見た目は見ない） |
| B1 | 号ごとの draft 反映許可 |
| B2 | 号ごとの見た目再判定 |
| B3 | 号ごとの写真 |
| C1/C2 | 語呂・相性の人OK |
| C3 | 5案実機の人OK |

## 着手順

1. cafe（01–03）の A1 → A2
2. 材料OK号のみ B1→B2（写真は別レーン）
3. 残りブロックも同じ型で A1→A2 を繰り返す
4. 十分な OK 文のあと統合（大きな相性改修は複数ブロック後）

詳細手順・自動化境界は Cursor Plan「見本文一括個別統合」と同内容。
