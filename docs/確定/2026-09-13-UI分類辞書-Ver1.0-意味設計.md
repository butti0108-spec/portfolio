## 第一階層

| 親 | 英語メモ | 役割 |
|---|---|---|
| 読む | Content | 読むための情報。Hierarchy（H1〜H4）を持つ |
| 操作する | Interaction | 操作できることを示す。Button／Selection Card／Toggle 等の親 |
| 状態を知らせる | System | **画面内で現在の操作・状態・制約を知らせる情報**。進行・結果・案内を含む |

---

## Content

- Hierarchy は **H1／H2／H3／H4** の4段階のみ。
- コンテンツ連動アイコン（⚠ 等）は文字列と一体で、同じ Hierarchy に追従する。

### 共通原則

1. **Hierarchy は Content だけ**に付く。System／Interaction には付けない。
2. **Hierarchy は読む順番ではない。意味の段階である。**  
   字が小さくても H2 になりうる。大きくても H4 や System になりうる。
3. **親が Interaction でも、中のタイトル／説明文は Content** になりうる（カード内階層）。
4. **見た目・※印・クラス名では分類しない。** 文章の役割で判定する。
5. **生成ホームページ本文は対象外。**

---

### H1

**現在の主面を代表するタイトル。**

「画面のタイトル」一般ではなく、**ユーザーがいま操作している面**の代表名。

- その面全体を一言で指しているか
- **同時に表示されても、ユーザーが操作している面だけが H1**（背面は一時停止）
- 原則、**アクティブな主面に H1 は1つ**

| 状況 | 文言例 | 判定 |
|---|---|---|
| 入口フル画面 | ホームページをつくる | H1 |
| 個別編集 | キャッチ文 | H1 |
| 編集ハブ | 編集ハブ | H1 |
| モーダル開中 | 自分で作る | H1（背面の H1 は一時停止） |
| 注文の右ペイン代表名 | 注文画面 | その主面の代表なら H1 |

---

### H2

**画面を意味ごとに区切る大きな見出し。**

問いはその代表例の一つ。問い以外の区切り見出し（例: 基本情報）も含む。

- 主面（H1）の**内側**で、大きな意味ブロックを分けているか
- 疑問形でなくてもよい
- 単一フィールドの名前なら H3（H2 にしない）

| 文言例 | 判定 | メモ |
|---|---|---|
| キャッチ写真に文字を載せますか？ | H2 | 問い（代表例） |
| 基本情報 | H2 | 区切り（問いではない） |
| いまの内容 | H2 | 区切り見出し（実証裁定） |
| 任意の追記 | H2 | 区切りブロック開始（実証裁定） |
| 店名（必須） | H3 | 項目名 |

---

### H3

**項目名。**  
何を入れるか／何についての欄・属性かの名前。

- 入力・選択・属性の**名前**か
- 面全体の代表名（H1）でも、大きな区切り（H2）でもないか
- Selection Card／Toggle の**カード内タイトル**も H3 になりうる（親UIは Interaction）

| 文言例 | 判定 |
|---|---|
| 店名／電話番号／タイトル | H3 |
| タイトルの大きさ／サブキャッチの行数 | H3 |
| 文字の下地（形）／下地の色 | H3 |
| 場所から編集（カードタイトル） | H3 |
| キャッチ文（画面全体の名） | H1（H3ではない） |

---

### H4

**項目・選択肢・対象について説明する読む補足。**

（覚え方：対象辞典。「これは何？」に答える。※比喩であり正式定義そのものではない。）

- 操作手順書・いまの案内ではない
- **細い段**：画面によっては存在しなくてもよい。必要なときだけ使う

> H4は、項目・選択肢・対象について「これは何？」に答える読む補足であり、操作・状態の案内（System）でも項目名（H3）でもない段である。

**出し方（2026-09-21 確定）**: 常時出すと本線が散らかる H4 は、**見出し右の小さな「？」＋ツールチップ**にしてよい。型の正本 → [`2026-09-21-見出し右ヒントマーク.md`](./2026-09-21-見出し右ヒントマーク.md)。

#### H4 ↔ System・二段判定

**第1判定（主）— 何を説明しているか**

| 説明しているもの | 行き先 |
|---|---|
| **対象そのもの**（これは何？／項目・選択肢・素材の意味・特徴・仕様） | **H4候補** |
| **現在の操作・状態・制約・結果**（いま何をする／いまどうなっている） | **System** |

**第2判定（補助）— 迷ったときだけ**

```text
「今」を抜いても、対象の説明として成立する？
  はい → H4寄り
  いいえ → System寄り
```

**「今」テストを主判定にしない。**

| 文言例 | 判定 | 理由 |
|---|---|---|
| ページの場所を選ぶ（カード note） | H4 | 選択肢は何か |
| 載せない場合は、写真だけの表示になります | H4 | 選択肢の結果説明（実証裁定） |
| 『下の枠』＝キャッチ写真の下に並ぶ小さな枠です | H4 | 対象の定義 |
| 推奨の比率は横16：縦9… | H4 | 対象の仕様 |
| 20文字以内で**入力してください** | System | 現在の操作制約 |
| 0 / 24 | System | いまの到達量 |
| 奥へ吸い込んでいます | System | 進行状態（loading）。見出し風でも Hierarchy ではない |
| step-help／コーチ／gate-lead | System | 現在の案内 |

#### H4を残す判断

| 案 | 結論 |
|---|---|
| A. H4残す | **採用**（対象説明を H3／System に潰さない） |
| B. H4削除 | 運用は可能だが境界が濁りやすい |

### カード内階層

```text
親UI … Interaction（Selection Card / Toggle）
 ├ タイトル … Content / H3
 └ 説明   … Content / H4（第1判定で「対象そのもの」の場合）
```

### モーダルと H1

> **同時に表示されても、ユーザーが操作している面だけが H1。**

背面のタイトルは一時停止。

## Interaction

親カテゴリ。下位:

| 下位 | 役割 |
|---|---|
| Button | 押して前進・戻る・副操作する |
| Selection Card | **画面・工程・目的など、大きな選択肢を選ぶカード**。Button ではない（見た目がカードでも、小さな同一画面内の択一は Toggle） |
| Toggle | 載せる／載せない、ラジオ的な択一、開示トグル等。**見た目ではなく、「状態を切り替える操作」を表す** |
| Icon Button | ±、▼ など操作示唆の共通部品 |
| **未分類** | Button／Toggle／Selection Card のどれにも無理に押し込まないときの仮置き。後で再分類する |

### Button の3段

| 段 | 役割 |
|---|---|
| 本線 | この画面の主前進（確定、これにします 等） |
| 補助 | 戻る、キャンセル、最初に戻す、その他の副操作 |
| 弱操作 | リンク風・弱い操作（ヘルプ、横断リンク等） |

- **最初に戻す**は補助（破壊寄り・稀用）。Destructive 専用段は作らない。

### Input

文字やファイルを入れる欄。Interaction の未分類寄り（別段を増やさない）。

---

## System

**画面内で現在の操作・状態・制約を知らせる情報。**

例: 進行中、成功、注意／エラー、手順の短い案内、文字数カウンタ、コーチ。

- 判定の目安: **「いま何をすればよいか／いまどうなっているか／いまの制約は何か」**
- **コーチ**は System。会話・表示名は「コーチ」。内部クラス（`.wizard-coach`）は当面維持。

---

## 迷ったときの5本

1. **いま何をすればよいか／いまどうなっているか／制約** → System  
2. **何について書いてあるか（項目・見出し・読む本体）** → Content  
3. **画面・工程・目的など大きな選択肢を選ぶカード** → Selection Card  
4. **同じ文脈での状態切替・択一**（見た目不問） → Toggle  
5. **押して前進・戻る・副操作** → Button（戻る／キャンセル／最初に戻すは補助）

どれにも無理なら Interaction／**未分類**（逃げ道）。押し込めない。

---

## 複合部品の扱い（実証メモ・新分類ではない）

全画面付箋で迷ったのは **辞書の穴ではなく、一塊のUIに複数の意味が同居する境界**だった。

運用:

- **意味ごとに分解して貼る**（例: 幅ヒント＝案内 System ＋ 切替 Toggle）
- ハニカム: **親（パレット全体）＝未分類**、**セル＝Toggle**
- 一段落に System と H4 が混在し分離できない場合は、**現状のまま主寄りの一方**（例: atelier-menu-lead＝System）。文章分割は将来の編集で検討

新しい親カテゴリ・例外ルールは設けない。

---

## 強調表現（意味側の指針のみ）

視覚の色・実装は定義しない。

- 強調は **稀用**
- **常用しない**
- 1画面あたり原則 0〜1（運用指針）

詳細な見た目は視覚設計の版へ。

## Ver1.0 に含めないこと

- 既存クラス名の一括置換
- 生成ホームページ本文への適用
- 新しい分類・新しい例外ルール
