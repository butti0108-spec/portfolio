## 本ツールの目的

> **用語を覚えることではない。**

目的は、**AI・設計者・実装者との会話を円滑にすること。**

スマホで5秒確認しながら、PCでクル／監査官と対話できること。

---

## 位置づけ

| 項目 | 内容 |
|---|---|
| 本体との関係 | ホームページメーカー本体とは**別ツール** |
| 正本との関係 | 意味の正本は **UI分類辞書**。本ツールは**解説・確認レイヤ** |
| データの流れ | `UI分類辞書 → 図鑑へ反映` の**一方向のみ**。逆（図鑑だけ独自定義）は禁止 |
| 対象ユーザー | 当面はアイシン専用（開発支援） |
| 利用シーン | スマホで開き、PCで対話 |

## 収録の優先順位

1. ホームページメーカーで実際に使う用語

3. 一般Web制作の共通知識  
4. その他  

（辞典の巨大化防止）

## 第1版の規模

- 用語: メーカー会話優先で十数〜三十語
- 1語: スクロール1〜2画面以内
- 技術: HTML＋JSON、DBなし
- 置き場: `tools/web-glossary/`（本体と分離）

### 1語の必須項目

読み／一言／親／メーカー実例／関連  

後回し可: 使い方・会話例・子分類（空欄可）

### UI

1. 検索（主）  
2. 親3カード（Content／Interaction／System）  
3. ツリーは任意

## 会話連動運用（監査承認・2026-09-13）

方針: **辞書を育てる時間を別途取らない。会話が辞書になる。**

### 回答末尾

見出しは **【設計用語メモ】**。その回に出した語だけ。知っていても出す（反復）。一言は図鑑 `oneLiner` に合わせる。

### 図鑑更新のタイミング

```text
会話 → 設計用語メモ（毎回）
     → ⭐語だけ candidates.md へ
     → 約10語／「まとめて反映」／「今すぐ辞書に」のときだけ terms.json＋yougo 更新
```

- **毎回 GitHub を更新しない**（履歴を散らさない）
- Cursor ルール: `.cursor/rules/design-terms-memo.mdc`
- 候補プール: `tools/web-glossary/candidates.md`
