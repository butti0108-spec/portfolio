# ソル運用：実装したら commit / push までセット（2026-09-21）

- 状態: 進行中（敦さん合意・クル指示）
- 対象: 主に `ポートフォリオ`（必要時 `kuru-hub` / `kurusorumessage`）
- 目的: 旧PC／新PC／クル／ソルで **開発中のズレをなくす**。クルは GitHub を見て確認する。

---

## 役割分担

| 誰 | やること |
|----|----------|
| **ソル** | 実装の区切りごとに **commit → push（`main`）までセット**。完了を連絡リポ `pending` に短く報告（hash 付き） |
| **クル** | ローカルだけ進めて正本にしない。**GitHub の差分・Pages を確認**して返す |
| **敦さん** | 本番公開・迷う判断・承認カード。普段の commit/push はソルに任せてよい |

ポートフォリオの GitHub は **見せる相手がメンター中心**なので、この運用で問題ない（秘密は載せない前提）。

---

## ソル：必須フロー（毎回）

1. **行動前**に対象リポで `git pull`（連絡リポも、書く前に pull）
2. 指示された範囲だけ実装（独断で広げない）
3. 動作の自分確認（壊したら戻す）
4. **同じ区切りで** `git add` → `commit` → `git push origin main`
5. `kurusorumessage` の `inbox/pending.md` に報告を追記して push  
   - 何をしたか（1〜5行）  
   - リポ名  
   - **commit hash**（短くて可）  
   - Pages を触ったら URL と「開ける／404」など一言  
6. 次の指示があるまで止める（勝手に次機能へ行かない）

「実装したけど push してない」「ローカルだけ直した」は **未完了** 扱い。

---

## commit の粒度

- **1区切り＝1つの目的**（例: 入口3択の仮UIだけ／ZIP読み込みだけ）
- 関係ないファイルを混ぜない（日誌だけ、など分ける）
- メッセージは英語短文でも日本語短文でも可。**何のための変更か**が分かればよい  
  例: `Add entry third path stub for ZIP resume`  
  例: `Fix kuru-hub p/ stubs for new manifest slugs`

---

## 触ってよい／禁止

### やってよい
- 指示されたパスの実装
- `docs/進行中/` への作業メモ・日誌追記（必要なとき）
- 区切りごとの commit / push
- 連絡リポへの報告・質問

### 禁止
- **Pages 入口の削除**（例: リポ直下の `index.html` / 必要な入口ページを消したまま push）
- 秘密・パスワード・トークン・個人の実メールをリポに書く
- 巨大 zip / 巨大バイナリを追跡に入れる（ignore 済み方針を崩さない）
- `docs/確定/` を独断で書き換え（案は進行中。採用はクル／敦さん）
- force push / `git config` の無断変更（identity は既定値で設定済みなら触らない）
- クル確認中に、同じファイルを黙って連続上書き（被りそうなら pending に「待ち」）


## クル側の確認の仕方（ソル向けの期待）

クルはだいたい次を見る。

1. GitHub 上の最新 commit と差分
2. 指示範囲を超えていないか
3. Pages 入口・主要 URL が死んでいないか
4. 問題なければ次指示。問題があれば直し方を pending / 伝言で返す

そのため **push されない変更は、クルからは存在しないもの** と同じ。

---

## 確認の型（2026-09-21 敦さん合意・クル伝言）

**工程のたびに敦さんが確認する型はやめる。** 次のバッチ型にする。

1. 敦さん＋クルで、直したい／作りたいを一度まとめる（いまのフェーズの範囲）
2. クルがソルへ、そのバッチ全部の指示を出す
3. ソルが実装する
4. ソルが、その部分を最初から最後まで自分でブラウザ通しする  
   （普通の操作＋戻り／連打／変な順／更新などありえない操作も）
5. 問題なければ完了報告（pending に「通しでやったこと」を書く）
6. そのあと敦さんが仕上がり確認＋微調整だけ

追加ルール:

- 途中で思いついたことは **いまのバッチに足さず** 次フェーズのメモへ
- フェーズ途中で作業を切り替えない
- **完了＝コード＋自分通し＋commit/push＋pending**。「動くはず」だけでは完了にしない

保存まわりの順序（変えない）: 区切り1 → 2 → 3（フォルダ）。寿司レイアウトは区切り3のあと。
