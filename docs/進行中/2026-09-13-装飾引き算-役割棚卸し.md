# 装飾引き算・役割棚卸し（Ver0.1）

- **日付**: 2026-09-13
- **仮説**: 安っぽく見える主因は装飾不足ではなく、**役割のない装飾の過多**である
- **目的**: 「何を足すか」ではなく **「何を消しても成立するか」** を一覧化する
- **対象**: かんたんホームページメーカー注文UI（`sample-1man/` 右ペイン中心。プレビューは編集の現在位置に関わるものだけ）
- **検証切替**: `?chrome=subtract`／ヘッダ「引き算」／`?v=ui-classify-v11-sub1`
- **関連**:
  - 視覚: `docs/進行中/2026-09-13-UI分類辞書-Ver1.1-視覚設計.md`
  - 余白: `docs/進行中/2026-09-13-業界標準-余白尺度調査.md`

---

## 判定の型

| 記号 | 意味 |
| --- | --- |
| **残す** | 役割が明確。消すと操作・状態が分からなくなる |
| **外して検証** | 役割が弱い／重複。余白・Hierarchyで足りるか確認 |
| **条件付き** | 余白だけでは不足なときだけ戻す |

消す前に聞く質問（3つだけ）:

1. この装飾は **どの役割** を伝えているか？（押せる／選択中／エラー／現在位置／区切り…）
2. Hierarchy・Vertical Rhythm・字の強さだけで、その役割は伝わるか？
3. 背景と枠が **同じ役割を二重** にしていないか？

## 「余白だけ」成立チェック（代表2画面）

検証前提: Hierarchy Phase1〜3 ＋ Vertical Rhythm（32→16→8）済み。引き算ON。

| 画面 | 余白＋Hierarchyだけで読めるか | メモ |
| --- | --- | --- |
| できること → キャッチ → 色／画像／文字 | **成立しやすい** | 実測 32／16／8。枠なしでも親子が分かる |
| キャッチ文編集 | **成立しやすい** | H1→項目→入力。fill-block枠なしでも可。入力欄枠は残す |

暫定結論（Ver0.1）:

> 代表編集画面では、**役割のない枠・地・影を外しても成立する**。  
> 足すべきは「派手さ」ではなく、**本線・選択・エラー・フォーカス・（必要なら）現在位置の代替**だけ。

## 業界整合（仮説の外部チェック）

| 出典 | 近い原則 |
| --- | --- |
| [Material 3 Spacing](https://m3.material.io/foundations/layout/grids-spacing/overview) | **Implicit grouping**（近接・余白）を先に。枠・影・outlineは Explicit が必要なとき |
| [Fluent 2 Layout](https://fluent2.microsoft.design/layout) | 余白でセクションを作れる。線や図形の区切りが必須ではない |
| [Atlassian Spacing](https://atlassian.design/foundations/spacing) | Group by proximity／Visual rhythm。Whitespace で階層 |
| [NN/g Visual Hierarchy](https://www.nngroup.com/articles/visual-hierarchy-ux-definition/) | 余白で足りなければコンテナ。余計な枠は clutter になるので sparingly |
| GOV.UK | タイポと余白が骨格。装飾より読み順 |

→ 仮説は業界の「Implicit first」と整合。引き算は奇抜ではなく本流。

## 設計原則（採用候補・Ver1.1へ反映）

1. **役割のない装飾は追加しない。**
2. **余白（Hierarchy・Vertical Rhythm）で成立するなら、背景・枠線は使わない。**
3. **装飾は「きれいに見せる」ためではなく、役割を伝えるために使う。**
4. **同じ役割を、背景と枠で二重にしない。**
5. **安く見せる原因を「装飾不足」と決めつけない。役割のない装飾の過多を先に疑う。**

### 操作境界（Selection／一覧）Ver0.1.1 — 2026-09-13

ChatGPT型を参考に、**文字を囲う枠**ではなく **操作エリア全体の境界**へ修正。

| 項目 | 内容 |
| --- | --- |
| 常時 | `1px solid rgba(0,0,0,0.08)`（ほぼ見えない） |
| Hover | 薄い地 `rgba(0,0,0,0.045)` ＋境界をわずかに濃く |
| Focus | 青系の薄い地＋outline（ヒット領域の外側） |
| 内側余白 | **12×16px**（≈0.8字）実測済 |
| 対象 | hub-entry／place／task の選べるボタン |
| キャッシュ | `?v=ui-state-v1`（色状態正式） |

目的は装飾増ではなく、引き算を保ったまま初見でも「ここは選べる」と分かること。
