## 対話の経緯（どうこの設計になったか）

### 1. きっかけ：左の番号の違和感

- **現象**: 左プレビューで「9｜8」「11｜10」のように、左の数字の方が大きい。上から1,2,3…とも並ばない。
- **気づき**: 右パネルは0〜17の**通し番号**、左は**場所に散らばったバッジ**。同じ数字体系なのに空間順と一致しない。
- **方向**: ペアは**左→右で番号昇順**。後に **色/文字の二系統番号** へ。さらに **色／画像／文字の三系統** へ。

### 2. ウィザード／アンケート型への転換

- **増渕さん案**: 右に全部見せない。はじめに→1問ずつ→次へで確定→左が育つ。最後に確認→ZIP。修正は左タップ。
- **クル**: 既存の `confirmStep`・左バッジ・ZIP と相性良い。右のフロー一覧は非表示でよい。
- **試作**: ウィザード骨組み（localStorage **v7**）、プリセット必須・ランダム履歴2段。

### 3. 「選ばせる」と「気づかせる」の転換

- **最初の仮説**: 方向性を先に決めればミスがない。
- **増渕さんの修正**: 作り始め時点では**本人も分かっていない**ことが多い（メガネレンズ作りと同型）。
- **結論**: 正解を先に選ばせず、**触った結果として自分のサイトが残る**。入口はどこからでもよい。漏れは**最後に1回**。

### 4. メガネ検査メタファー（色決めの本命）

- **体験**: 「前と後、どっち？」の**二択**→一項目ずつ確定→試着→部分修正も再び二択。
- **適用**: **色だけ**メガネ式。**文字・画像**は本人入力。
- **入口**: ガイド／セルフの**モード選択は1回**。明確な人は次へ連打・一覧スクロール。

### 5. 2モード＝情報密度の正反対

| ガイド | セルフ |
|--------|--------|
| 情報最小・大文字・余白多 | 説明削減・カテゴリ圧縮・縦スクロール一気 |
| 丸ゴ・戻る大きめ・安心 | 角張り・戻る｜次へ同格 |
| 1問ずつ | 色→画像→文字を一覧で好きな速度 |

### 6. UX摩擦の除去

- **次へ** … 戻ると**同サイズ・同色**（セルフ）。ガイドのみ戻る大きめ可。
- **毎回の confirm** … **廃止**。次へ＝**黙って確定**（バーの該当番号が緑）。
- **章境目** … 全面オーバーレイなし。上バー＋応援1行（「あとN問」）。**所要時間は出さない**。色→画像／画像→文字で応援1行。
- **提出** … チェック5項目 → **提出の確認** → **ZIP（最下）**。全面オーバーレイなし。
- **説明の正本** … 1万円ページ・ポートフォリオFAQへリンク。はじめにFAQは削除。
- **JSONコピー** … 削除（ZIP内 `order.json` で足りる）。

### 6b. 上固定・進捗バー（2026-08-29 確定 → 三章に更新）

- **色0＋色1〜10／画像0＋画像1〜4／文字0＋文字1〜9** の番号マス。章ごとに**3段**（ラベル＋番号）。0は注意ステップ（破線）。薄青／橙／薄赤 → **次へで緑**。タップでジャンプ。
- 進捗バー直下は**1行**（例：`色3・ヘッダー色｜あと14`）。コーチ・エラーは必要なときだけ（「わかった」パネルは使わない）。
- 公式用語：**見本サイト**／**注文画面**／**依頼ファイル（ZIP）**。「プレビュー」「サンプル画面」はお客様向けに使わない。配置の説明では「左側」「タブ」を使ってよい。
- **反映タイミングの正本**は注文画面「はじめに」（長くて正確でよい）：色は選んだその場で見本サイトへ。写真・文字は選んだ／書いたその場で見本サイトへ（「次へ」は確定して進む操作）。
- 見本凡例は色見本＋作業名のみ：**色の選択／画像の選択／文字の入力／完了**（「青＝」は二重なので書かない）。
- 下書き説明は注文画面**上部のアコーディオン**。新規開始・下書き復帰時は**開く**。「次へ」で**閉じる**。「途中再開」タグは置かない（開いた下書き枠が再開の合図）。
- 書体選択は**カード一覧**（12種・名前だけのコンパクト表示。確認は左の見本サイト）。説明文の連打はしない。
- **はじめにの用途選択**（個人紹介／会社・教室／お店／実績・事例／サービス・メニュー）：**用途**と**進め方**は別ステップ。用途は選んで「次へ」、進め方はガイド／セルフの二択で即進む。選ぶと**左の見本に仮文**（入力欄は空＋プレースホルダー）。一文字入力で左は入力内容へ。テンプレ集ではない。同義語の例示はしない。
- 提出：チェック → 提出の確認 → **依頼ファイル（ZIP）説明は提出ブロックに1** → 保存。
- **ヒーロー中央に大きく「これは見本です」のみ**。
- ヘッダーは**本物メニューに見せない**。空のときは注釈を**2段**。
- サンプル画面のダミー文は**中立プレースホルダ**。
- サンプル画面上段：**2段**（1段目＝凡例の折り返し可／2段目＝幅スライダー＋端末目安＋**PCで見る**＋番号＋はじめに）。幅は連続変更（おおよそ〜480スマホ／〜1024タブレット／それ以上PC）。分割中の最大がPC未満なら「タブレット（最大）」などと出す。**PCで見る**で注文を隠し見本を全幅表示→「注文に戻る」で復帰。

### 6c. 文言原則（2026-08-29）

- **1メッセージ＝1役割＝原則1か所**。言い回しを変えた同趣旨の連打はしない。
- お客様向け説明は**メモ書きにしない**。短い段落に分け、余白・改行・行間を確保（`.dash-note-block`）。
- 各項目のヘルプ導線は **「ヘルプはこちら」** 1行（タイトルで文脈が分かる）。提出だけ ZIP／範囲など名前付きリンク可。
- 注文画面ヘッダーに **最初から作り直す**（端末の下書き全消去・2段確認）。ヘルプボタンと離す。
- **忘れ防止・漏れ防止**として、離れた場所に短く置くのは可（例：画像は下書きに残らない／送るまで依頼は始まらない）。防止用は枠・改行して読みやすくしてよい。
- なくても成立する重複は削る。
- 注文画面リードは短く：**あとから直せます**（ヘッダー1行）。
- **画像章の共通説明**は **画像0** に1回。キャッチ（画像1）はファイル選択のみ。「なくても可」「あとから送る」は禁止。
- **文字章の共通説明**は **文字0**（文字数上限など）。**色章の共通説明**は **色0**。
- サンプル画面のバッジは **1から**（0は注文画面の進捗専用）。
- **文字数**：各欄ごとに上限（ちょうどまで可）。下に `現在 / 上限`。超えなら次へ不可（注意は進捗下の1行。わかったボタンなし）。
- **写真**：取込時リサイズ（ヒーロー長辺1920／その他1600／ロゴ800・JPEG）。1枚項目（キャッチ・ロゴ）は未選択で次へ不可。枚数項目は選んだ枚数ぶん必須（＋/−でサンプル画面の枚数も即反映）。不足時はZIP不可。枠は cover トリミング（目安：キャッチ約16:9、自己紹介約4:3、実績は横長）。画像0で案内。
- 注文画面ヘッダーは**1行**＋その下に下書き枠。進捗は厚くしない。
- 「はじめに」にルールを完結させる（外の凡例参照にしない）。
- **ガイド**＝1項目ずつ確認しながら進めたい人。**セルフ**＝順番やペースを自分で選びたい人（初めて／慣れではない）。

### 6d. ガイドの章解放（作成ゲーム寄りの分かりやすさ）

- **ガイド** … 前の章が全部完了するまで次章は開けない（色→画像→文字）。進捗・バッジ・注文の開閉すべて同じ判定。
- **セルフ** … **章ロックなし**。表（アコーディオン全部閉じ）から行を開く → 中央 **確定** → 緑の行のまま表に戻る（触っただけでは緑は消さない。再 **確定** で反映）。**戻る**なし。**はじめに**だけ **次へ**（モード選択後は表へ）。
- ロック中（ガイドのみ）は押せない沈黙にしない。**「色の選択が全部完了すると、画像の選択と文字の入力ができます」** など、何ができるかを書く。
- 進捗1行は **「あとN項目で完了」** まで書く。幅に余裕があるときだけ短い応援（残り15〜11：半分を過ぎました／10〜6：もう少しです／5〜1：あと少しです）。狭い幅では応援だけ隠す。
- 制作フロー一覧・工程内の「確定する／やり直す」は廃止（進捗＋次へに一本化）。提出の「提出の確認」は残す。

### 7. 色のフィードバック

- **コントラスト警告／物差し** … 廃止・見送り
- **色の選び方（2026-08-29 更新・タブ確定）**
  - 基本は **12色**だけ（白／クリーム／黄／橙／赤／桃／紫／青／水色／緑／茶／黒）
  - 各色にタブ：**「色を選ぶ」**／**「カラーコードで指定」**
  - 「色を選ぶ」：12色＋**濃さバーを常時表示**（無段階）
  - 「カラーコードで指定」を選んだ瞬間 → **その項目のプレビューは強制で白**（コードの形式・正誤は問わない）
  - カラーコード欄は **生文字のまま保存**（Hex／RGB／8桁など何でも可）。画面ではパースしない。納品時にクルが解釈して反映
  - 調べ用に MDN カラーピッカーへリンク
  - 粒ボード・つぼ混ぜ・スポイトは削除
- **帯／ヘッダー** … お客様向けは **ヘッダー・フッター**（色2・色3）。進捗短称は「ヘッダー背景／ヘッダー文字」
- **見本枠1／見本枠2** … 旧「自己紹介／実績」。用途は固定しない。注文画面は「枠の名前」。「かたまり」は使わない
- **提出の大きな色コード一覧** … やめて各色工程へ寄せた。`extra_notes` は色以外の連絡用
- 工程内「確定する／やり直す」行は DOM から削除
- 下書きキー `sample-1man-order-v13`（`colorModes` + `colorCodes`）

### 8. 左バッジ：青／橙／赤／緑

- **色** … **青** 1–9

- **文字** … **赤** 1–11（見出し2／キャッチ書体3／本文書体6・提出＝11）

- ガイド: `guidedImageUnlocked` / `guidedTextUnlocked` で後章ロック

- 安心の「あとから直せる」は注文画面リードに1回だけ（工程内で連打しない）

### 10. ガイド第2〜3章 — 2026-08-29 確定

- **表記・入力項目はセルフと同じ**（同じ `dash-block` 中身）。
- **レイアウトだけガイド向け**（大文字・余白・1問ずつ提示）。
- 色ほど二択にはしない。

### 11. 章分けの実務ルール（v7）

- **Works件数 (+/−)** … 画像章 `works-images` のみ。文字章 `works-text` は件数UIなし（`data-fill-for="works-list"` で同期表示）。
- **About写真枚数** … `about-images`。アコーディオン数は `about-text`。

- **その他** … `extra-content`（営業時間／アクセス／**住所**のONと文。地図埋め込みは出さない）→ そのあと `contact-text` → `finish`。

- **提出** … 参考URL・納品希望日・連絡手段は無し。納品目安は1〜2週間の固定案内。その他希望はレイアウト変更以外・可否は後日連絡。

## 12. ガイド色・試着UI（2026-08-30 試作）

Coolors 型の**仕組み**（1スロットだけ候補を回して固定）を、**横ストリップではなく試着型レイアウト**で試作。セルフの12色UIはそのまま。

### フェーズ

| フェーズ | 画面 |
|----------|------|
| **プリセット** | 5種プリセット＋色1〜10グリッド |
| **分岐** | **この雰囲気のまま** → 色一括確定→画像1／**1色ずつ直す** → 試着 |
| **試着** | **左＝前／右＝今（＝プレビュー）**。**戻る｜この色で確定｜次** |
| **濃さ** | 「この色で確定」のあと。濃さバーのみ → **この濃さで次へ** |
| **12色** | いまの色が選択済み。触ってもすぐ戻らない。**この色にする**で試着へ |

### 試着の操作

- **次** … 候補を出し、すぐプレビューへ。ひとつ前は「前」へ
- **戻る**／**前タップ** … 前⇔今の入れ替え（文脈どおり）
- **この色で確定** … 色合いOK → **濃さ調整**へ
- **この濃さで次へ** … 工程確定→次の色項目へ
- 案内例: 「次で色合いを試せます。濃さは、色を決めたあとに調整できます。」
- **12色で自分で選ぶ** … 色・濃さを調整 → **この色にする** で試着へ（カラーコードなし・`#`表示なし）
- 下の色チップ列は置かない

### コード

- `sample-1man/index.html` … `#guided-color-trial`
- `sample-1man/script.js` … `setupGuidedColorTrial` / `syncGuidedColorTrial`
- `sample-1man/sample-overrides.css` … `.guided-color-trial` 以下
- 下書き **v10** … `guidedColorPhase`（`preset` / `tune` / `shade` / `pick`）等
