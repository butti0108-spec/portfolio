## 流派マップ（グリッド）

| 流派 | 基準 | 本サンプルでの採用 | 例 |
|---|---|---|---|
| **A. 8px 基調** | 8 の倍数＋半分（4） | **多数派** | Atlassian, Carbon, USWDS, Primer(古典), Spectrum 系 |
| **B. 4px 基調** | 4 の倍数（8も含む） | **多数派（Web UIキット）** | Polaris, Fluent, Ant, Chakra, Tailwind |
| **C. 5px 基調** | 5 の倍数 | **少数（公的UI）** | GOV.UK |

**読み方**: A と B は対立ではなく、**実務上どちらも「4の倍数に乗る」**。  
差は「基本の呼び名が 8 か 4 か」。GOV.UK だけ別レール。

### 集計：基準グリッド（n=18）

| 指標 | 結果 |
|---|---|
| 最頻値 | **4px 刻み（＝8px リズムに乗る）** |
| 中央値 | 4px 刻み |
| 上位80%帯 | 4px または 8px 基調（ほぼ同族） |
| 5px 流派 | 1/18 ≒ **6%**（GOV.UK） |
| 採用率（4または8） | **17/18 ≒ 94%** |

**推奨**: メーカーUIは **8px リズム（4px 刻み可）**。GOV.UK 方式は採用しない（公的フォーム特化のため）。

## 役割別余白（推定ルール）

多くの DS は「H1→本文 = 24px」と**一行では書いていない**。  
代わりに **spacing の用途帯**から写像する（Atlassian: 小0–8／中12–24／大32+、Polaris card padding=16 等）。

| メーカー用語（Ver1.0） | 写像する DS 用途帯 | 推定標準帯 |
|---|---|---|
| H1 → 次の内容 | 中〜やや大 | **16–32px**（最頻寄り **24**） |
| H2 → ブロック内 | 中 | **12–24px**（最頻寄り **16**） |
| H3 → 入力欄 | 小 | **4–12px**（最頻寄り **8**） |
| H4／System → 対象 | 密着〜小 | **4–8px** |
| フォーム項目間 | 中 | **12–24px**（最頻寄り **16**） |
| カード padding | 中 | **12–24px**（Polaris 明示 **16**） |
| ボタン padding | 制御トークン | **縦8×横16** 近傍が厚い |
| セクション間 | 大 | **24–48px**（最頻寄り **32**） |

GOV.UK 補足: 大画面で h2 下 **30px** など（5px 系）。8px 系に丸めると **24–32**。

## Hierarchy垂直リズム（追補 Ver0.1.1・2026-09-13）

監査官提案どおり、**余白全部ではなく Hierarchy 間の垂直距離**に絞る。  
グリッド調査（4/8px系94%）は前提のまま。ここは「関係ごとの階段」を埋める。

### 方法

1. 明示マージンがある DS を優先（GOV.UK headings CSS、Ant Form／Typography、Bootstrap reboot、USWDS prose設定）  
2. 明示がない DS は **用途帯＋近接原則**から写像（Atlassian／Carbon／Fluent／M3）→ 表では「写像」と注記  
3. GOV.UK の **5px系**は 8px リズムへ丸めた値も併記（採用はしないが参照）  
4. 単純平均は出さない。最頻寄り／中央寄り／推奨帯

### 共通原則（複数DSで反復）

| # | 原則 | 根拠の厚い例 |
|---|---|---|
| ① | **H1は上より下を重視**（ページ開始→次内容への呼吸） | Apple HIG Layout（慣習）／GOV.UK heading は `margin-top:0`＋大きめ `margin-bottom` |
| ② | **H2は下の中身と1グループ**。前セクションとの距離の方が広いことが多い | Atlassian Group by proximity／Visual rhythm |
| ③ | **H3／Labelは入力と近い**（一組） | Ant Form `verticalLabelPadding` 下8／Atlassian small 0–8 |
| ④ | **親より子に近づく**（兄弟グループは遠い） | Carbon「近接で関係」、Ant Proximity 8／16／24 |
| ⑤ | **同じ間隔の連打を避け、階段リズム**（例 32→16→8） | Atlassian Visual rhythm／Ant 縦 `y=8+8n` |
| ⑥ | **見出しは前より後に密着**（上≧下×1.5 が目安） | [USWDS Typography](https://designsystem.digital.gov/components/typography/) |

### メーカー画面への写像（監査官例）

問題の見え方（上が広すぎ／下が同格）:

```text
できること
　40？
キャッチ　　← 別ブロックに見える
　32？
色
```

近接どおりの階段（推奨）:

```text
できること          （親 H2）
　32                 ← Section／親の下は「子グループまで」やや広めでも可。子同士は狭く
キャッチ            （子グループの見出し）
　16                 ← H2→中身
色                  （H3）
　8
画像
　8
文字
```

読み替えルール（感覚→設計）:

| 感覚 | 設計ルール |
| --- | --- |
| 「キャッチを2個分上げたい」 | **親→子グループは16帯、孫（H3→入力）は8帯**に揃え、兄弟セクションだけ32 |
| 「全部スカスカ／全部カチカチ」 | **Visual rhythm**: 32→16→8 の階段を保つ。16連打にしない |

### 現行 Phase1 当てはめとの関係

| 関係 | Phase1 適用値 | Ver0.1.1 | 判定 |
| --- | ---: | ---: | --- |
| H1→次 | 24 | 24 | 一致 |
| H2→中身 | 16 | 16 | 一致 |
| H3→入力 | 8 | 8 | 一致 |
| セクション | 32 | 32 | 一致 |
| Input→Input | 16 | 16 | 一致 |
