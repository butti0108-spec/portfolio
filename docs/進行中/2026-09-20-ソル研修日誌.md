## 研修2メモ（実装前ブリーフィング）

### 意味からのUIとは
見た目（色・余白・サイズ）の前に、「その部品は何の役か」を決める。Content（読む）／Interaction（操作）／System（状態を知らせる）を混ぜない。Hierarchy は字の大きさではなく意味の段階。色も装飾ではなく状態の言語（白＋グレー枠／操作中は緑枠だけ）。

### 1万円メーカーの流れと順の理由
入口2択 →（サンプルなら）回転寿司で見本を掴む → 用途 → 色 → 基本情報 → 枠ごと文章 → 画像 → 作成演出 → 出す／直す。  
理由: 1画面1問い。本番プレビューを早く出しすぎると迷いが増える。細かく触りたい人だけ編集ハブへ。分岐後は他経路に流入しない。

### レイアウトを触るとき守ること
- 動線を増やさない（本線に選択肢を足さない）
- 意味の分類を見た目で上書きしない
- 確定 docs の本文を要約で潰さない
- サンプル本線と編集ハブの役割を混ぜない
- Pages 入口（index / mentor）を消さない
